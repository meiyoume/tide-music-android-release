# 潮汐音乐 · 手机版 UI

纯前端手机版音乐 App 界面原型。**零依赖**：没有框架、没有构建、没有外部字体和图片，
双击 `index.html` 就能打开。

- 视觉：**6 套皮肤** × 深色/浅色两种模式，另有 6 种主题色可在皮肤内单独替换；
  封面和播放页背景全部由 CSS 渐变生成
- 范围：首页、榜单、搜索、我的、歌单详情、全屏播放页（封面/歌词双视图）、播放队列，
  以及设置页和 **8 个设置子菜单**
- 交互：真实可点，播放进度会走，主题和偏好刷新后保留

## 打开方式

直接双击 `index.html`（`file://` 可用，所有 `localStorage` 访问都做了 try/catch 降级）。

需要局域网/手机实机预览时再起个静态服务：

```bash
cd music-ui-mobile
python -m http.server 8777
# 手机访问 http://<你电脑的IP>:8777
```

浏览器窗口宽度 ≥ 640px 时会自动套上手机外框（含模拟状态栏），方便桌面预览；
窄屏则铺满全屏，就是真机效果。

## 两种数据源

同一套界面跑在两种数据源上，由 `api.js` 自动选择：

| 环境 | 后端 | 数据 |
| --- | --- | --- |
| 浏览器直接打开 | `mock` | 内置演示数据 + 模拟播放 |
| 装进洛雪安卓版（WebView 里） | `native` | 内核桥接：真实音源、真实播放、真实歌词 |

判定方式是有没有 `window.ReactNativeWebView`。界面代码（`app.js`）不认识任何具体数据源，
只调 `window.Tide.*`，加/换数据源不用动界面。

在 App 里的接法、桥接协议、以及踩过的坑，见洛雪工程里的 `TIDE-ANDROID.md`。

> 改了界面记得跑 `node tools/sync-tide-assets.mjs`（在洛雪工程里）同步进 APK，
> 并把 `index.html` 里的 `?v=` 版本号 +1 —— WebView 会缓存资源，不加版本号会出现
> 「装了新版但界面还是旧的」。

## 设计约定

**颜色**：全部走 CSS 变量，换主题只改 `data-theme`，换主题色只改 `--accent`。
强调色克制使用——只在选中态、播放指示、主按钮上出现，不给图标上色。

```css
--bg / --bg-elev / --card / --hairline     /* 层次 */
--text / --text-2 / --text-3               /* 三级文字 */
--accent                                    /* 由 JS 注入，6 色可换 */
```

**圆角**：卡片 22px、大卡 28px、输入框 16px、小控件 12px（`--radius-*`）。

**动效时长阶梯**：`.1 / .15 / .2 / .3 / .5 / .75s`，**没有 `.4s`**。
页面入栈用 `.3s` 的 `cubic-bezier(.32,.72,0,1)`。

**图标**：24×24 描边风格，`stroke-width:1.7`，统一 `currentColor`。
新增图标只要在 `index.html` 的精灵图里加一个 `<symbol id="i-xxx">`，
然后用 `<svg class="icon"><use href="#i-xxx"/></svg>` 引用。

## 皮肤

六套皮肤，每套都是一套完整的深色 + 浅色底色令牌，外加**一组专属的专辑封面配色**——
这是换肤感的关键，只换强调色会显得很敷衍。

| 皮肤 | `data-skin` | 气质 | 签名主题色 |
| --- | --- | --- | --- |
| 墨黑 | `ink`（默认） | 近黑中性，克制 | 薄荷 `#3ECFB2` |
| 午夜 | `midnight` | 紫夜霓虹，环境光偏玫红 | 星紫 `#7C6BFF` |
| 深海 | `abyss` | 蓝黑冰调，安静通透 | 晴空 `#4EA8FF` |
| 暖砂 | `dune` | 暖褐琥珀，纸与木头的质感 | 琥珀 `#FFB454` |
| 樱雾 | `sakura` | 粉白柔光 | 蔷薇 `#FF6BCB` |
| 赛博 | `cyber` | 纯黑高对比，电光绿 | 青柠 `#4ADE80` |

皮肤和主题色是**两层，可以叠加**：皮肤决定底色、卡片质感、环境光、封面配色和签名主题色；
切换皮肤时会套用签名主题色，但之后仍可单独换成任意主题色。

### 加一套新皮肤

在 `styles.css` 里加三个块（照抄任意一套改颜色即可）：

```css
/* 1. 深色底色 */
html[data-skin="新名字"][data-theme="dark"]{ --bg:…; --card:…; --text:…; … }

/* 2. 浅色底色 */
html[data-skin="新名字"][data-theme="light"]{ … }

/* 3. 封面配色（a–h 八个键，每键两个端点色） */
html[data-skin="新名字"],
[data-skin-preview="新名字"]{
  --c-a-1:…; --c-a-2:…;  /* … */
}
```

再去 `index.html` 的 `.skins` 里加一个按钮，`app.js` 的 `SKINS` 里加名字和签名主题色，
最后在 `app.js` 的 `[data-skin-preview="…"]` 那两组里补上小样取值（深色一份、浅色一份）。
不需要动任何渲染逻辑——封面和播放页背景都是从 CSS 变量读的。

### 封面怎么来的

`.cover--a` ~ `.cover--h` 是八个渐变类，两端色取自皮肤变量：

```css
.cover--c{ background-image:linear-gradient(140deg,var(--c-c-1),var(--c-c-2)); }
```

播放页背景和歌单头部这两处大面积用色由 JS 拼同样的渐变（`coverGradient()` 读同两个变量），
所以换皮肤时它们自动跟着变，颜色只在 CSS 里维护一份。

要换成真图，把 `<span class="cover cover--c">` 改成带 `style="background-image:url(...)"` 即可，
`.cover::before/::after` 的高光层会自动叠加。

## 怎么改数据

全部数据集中在 `app.js` 顶部：

```js
TRACKS        // 16 首歌：{ t 歌名, a 歌手, al 专辑, d 时长(秒), c 封面色键 a-h }
PLAYLISTS     // 首页「为你精选」
MY_PLAYLISTS  // 我创建的歌单
FAV_PLAYLISTS // 我收藏的歌单
CHARTS        // 榜单
HOT           // 热搜
LYRICS_POOL   // 3 组歌词，按歌曲下标轮流用；每行 { t 起始秒, x 正文, tr 翻译 }
```

封面不是图片，是 `.cover--a` ~ `.cover--h` 八个 CSS 渐变类，两端色来自当前皮肤的
`--c-*-1` / `--c-*-2` 变量（见上文「皮肤」一节）。改封面配色改皮肤变量，不要改 `app.js`。

## 交互实现说明

- **导航**：标签页切换 + 子页面入栈/出栈（`pushSub` / `popSub`），逐级返回有回退动画
- **播放**：`setInterval` 每 250ms 推进进度，驱动进度条、迷你播放器和歌词滚动；
  进度条支持指针拖拽
- **歌词**：点封面 / 点歌词在「封面视图」与「歌词视图」间切换，当前行会自动居中
- **迷你播放器**：未播放时不出现；进入设置类系统页面自动收起让位
- **设置项**：开关、单选圆点、分段控件、步进器、滑块都是真实状态；
  「播放模式」的分段控件与播放页的随机/循环按钮双向联动
- **播放模式**的分段控件与播放页的随机/循环按钮双向联动
- **偏好持久化**：皮肤、主题模式、主题色写入 `localStorage`（键前缀 `tide.`）

## 已知边界

- 没有音频文件，播放是模拟的：进度会走，但不出声
- 所有数据为虚构演示内容，封面为 CSS 渐变，非真实专辑图
- 设置里的部分操作（客服、协议、系统存储管理等）只弹 toast，未接真实页面
- 桌面端手机外框只在宽 ≥ 640px 且高 ≥ 780px 时出现
